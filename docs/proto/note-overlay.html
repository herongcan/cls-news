屏宽

320 是 iPhone SE 一代 / 小米小屏的下限，用来验「两行会不会变三行」。

为什么这么放

不和按钮抢位置。「刷新」在右上角，note 说的是刷新为什么没生效，贴在它旁边会被读成按钮的一部分。

不并进 meta。meta 是「结果的身份」：什么时候生成、多少条材料、几条主线。note 是「这次动作的结论」，两者生命周期不同——meta 变说明换了结果，note 变只说明你点了一下。

但降级必须显形。note 说「已回退上一版」时，用户看的其实是旧内容，纯灰字会被当成装饰跳过，所以要转琥珀 + 加圆点 + 挂「旧版」徽标。

把「不服」变成动作：用户看到「未达阈值」往往就是想强算一次。代价是接口要加 bypass 参数，且必须在点击时提示要花多少钱。

量出来的三个事实（2026-11-28 定稿）

  • 标题区可用宽只有 290 / 264 / 224px（390 / 360 / 320），因为右边站着「刷新」。11.5px 下大约对应 25 / 22 / 19 个字，不是屏宽除以字号。
  • 改前的文案最长 29 字（表格最后一行），390px 上也折两行，第二行只剩「防结论逐代漂移」这种半句。没人量过，它就那么在代码里躺了一版。
  • 现在七句话全部压到 ≤16 字，三档屏宽都单行 —— 连带「旧版」徽标的回退提示也一样（徽标占掉约 3 个字）。
  • 所以 Strategy.MAX_NOTE_WIDTH = 18 是可执行断言，不是注释：NoteCopyTest 5 条盯着它，改文案改超了直接红。
  • 过程量（日期、字符数、今日第几次）现在只进日志：prepare 里一行 mode/reason/added/deltaToday，够定位，也不占浮层的宽度。
  • C 方案的「重算」只在 cached=true 时出现——那正是用户被缓存挡住、最想强算的时刻；其余场景挂个重算按钮纯属多给一次花钱的机会。这一条还没做，等浮层骨架跑起来再定。
